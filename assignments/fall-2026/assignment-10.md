**Predict → Build It → Use It → Ship It → Verify**

Bundle [Lesson 15](../../lessons/15-division-of-labor-capstone/README.md) into one submission. Lesson Assessments are ungraded practice.

## Predict

Which delegation decision in your own workflow is most likely to change under scrutiny? Register acceptance conditions and a possible counterexample. Preserve the original before receiving output or critique.

## Build It

Build a bounded Python workflow and an evidence-backed task map spanning at least three relevant tiers. Include one substantive mechanism from earlier lessons and the checks necessary to evaluate it.

## Use It

Use Claude Code to implement and critique the workflow. Revise the task map using actual evidence. Keep a dated capability assessment separate from the taxonomy and identify concrete human work.

## Ship It

Submit working artifact, task map, contribution record, evidence, Frictional log, and handoff memo. Include the Python implementation, tests, inputs, evidence, README, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md. Identify source material and real assistance. The final version goes to the designated GitHub location and Canvas.

## Verify

Reproduce from declared inputs. Trace a claim to evidence, test a failure boundary, and revisit the first lesson's prediction. Defend a limitation without asserting that all future AI systems must share it.

Check the shipped candidate, record actual outcomes, and explain the bounded conclusion. Do not fabricate human participants, permissions, findings, or understanding. If a learning exercise uses a simulation, label it throughout.

## Division of labor

**AI should** draft, compute, implement, and challenge the candidate.

**Human should** practice the mechanism, verify the evidence, maintain actual relationships, and own the final handoff.

For implementation rows, award full points for complete evidence, proportionate partial credit for a documented partial implementation, and zero when the required evidence is absent. Explain deductions. The technical handoff row assesses usability and understanding; GitHub points assess delivery. Frictional assesses the actual process, not whether the result succeeded. A finding that survives the audit can earn full credit when checks are discriminating and scope is honest.

An explainer video or Brutalist production is optional and may support communication quality within Relative Quartile. It has no separate points; excellent written evidence can earn full credit. Claude Code is assumed; direct API calls and paid media tools are unnecessary.
