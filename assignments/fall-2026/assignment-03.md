**Predict → Build It → Use It → Ship It → Verify**

Bundle [Lesson 4](../../lessons/04-embodied-feedback/README.md) into one submission. Lesson Assessments are ungraded practice.

## Predict

Will a written procedure predict all the feedback needed to sort a few harmless household objects? Record an expected mismatch. Preserve the original before receiving output or critique.

## Build It

Build a Python observation log comparing planned step, observed outcome, uncertainty, and adjustment. Define units and observation categories; use an accessible alternative task when needed.

## Use It

Ask Claude for a simple sorting procedure, then perform the task yourself or analyze a clearly labeled supplied observation trace. Note feedback unavailable from the original text.

## Ship It

Submit procedure, observation log, parser, and adaptation note. Include the Python implementation, tests, inputs, evidence, README, PREDICTIONS.md, CONTRIBUTIONS.md, FRICTIONAL.md, and VERIFICATION.md. Identify source material and real assistance. The final version goes to the designated GitHub location and Canvas.

## Verify

Test missing observations and contradictory units. Distinguish an actual physical trial from a text simulation; neither proves all robots lack the capacity. Avoid collecting sensitive personal measurements.

Check the shipped candidate, record actual outcomes, and explain the bounded conclusion. Do not fabricate human participants, permissions, findings, or understanding. If a learning exercise uses a simulation, label it throughout.

## Division of labor

**AI should** draft a procedure and organize observations.

**Human should** perform or accurately label the observation task, notice feedback, and decide adjustments.
