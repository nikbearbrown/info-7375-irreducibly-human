# Lesson 15 — Build and defend the division of labor

**Predict → Build It → Use It → Ship It → Verify**

Reading: [08 conclusion.md](../../chapters/08-conclusion.md) — “The recursive capstone.” Tools: Claude Code and Python standard library. Prerequisites: prior lessons and retained predictions/evidence. Suggested pacing: one class session plus practice; Canvas supplies dates.

## Predict

Which delegation decision in your own workflow is most likely to change under scrutiny? Register acceptance conditions and a possible counterexample. Save an original expectation, confidence estimate, assumptions, and possible falsifier in PREDICTIONS.md before seeing the output. Add later observations without rewriting the original.

## Build It

Build a bounded Python workflow and an evidence-backed task map spanning at least three relevant tiers. Include one substantive mechanism from earlier lessons and the checks necessary to evaluate it. Make an initial attempt before requesting a complete solution. Work in learning-artifacts/15-division-of-labor-capstone/ with main.py, test_main.py, inputs, and outputs. Explain what the mechanism checks and what it cannot determine.

## Use It

Use Claude Code to implement and critique the workflow. Revise the task map using actual evidence. Keep a dated capability assessment separate from the taxonomy and identify concrete human work. Record date, model identifier as displayed, relevant prompts, commands, and actual results. Label fixtures, simulated participants, and hypothetical decisions. Claude Code is assumed; direct API calls are optional and may require separate credits.

## Ship It

Deliver working artifact, task map, contribution record, evidence, Frictional log, and handoff memo. Include a README with exact run/test commands and source credits, plus the [prediction, contribution, Frictional, and verification records](../../templates/README.md). Package a local candidate for inspection; the [Assignment map](../../assignments/fall-2026/README.md) specifies final delivery.

## Verify

Reproduce from declared inputs. Trace a claim to evidence, test a failure boundary, and revisit the first lesson's prediction. Defend a limitation without asserting that all future AI systems must share it. Run checks on the packaged candidate. Record outcomes and remaining limits in VERIFICATION.md; revise and repeat Ship It → Verify when needed. Explain what changed in your understanding, without inventing difficulty or a required conclusion.
