# Lesson 5 — Evaluate helpful language without inventing a relationship

**Predict → Build It → Use It → Ship It → Verify**

Reading: [03 tier 3 social and personal.md](../../chapters/03-tier-3-social-and-personal.md) — “The performance is real; that is the trap.” Tools: Claude Code and Python standard library. Prerequisites: prior lessons and retained predictions/evidence. Suggested pacing: one class session plus practice; Canvas supplies dates.

## Predict

Will a warm response also respect the facts and boundaries of a fictional interaction? Predict a concrete failure. Save an original expectation, confidence estimate, assumptions, and possible falsifier in PREDICTIONS.md before seeing the output. Add later observations without rewriting the original.

## Build It

Build a Python response-review ledger for factual support, promises, uncertainty, tone observations, and escalation boundaries. Automated flags are review suggestions, not a measure of empathy. Make an initial attempt before requesting a complete solution. Work in learning-artifacts/05-social-language/ with main.py, test_main.py, inputs, and outputs. Explain what the mechanism checks and what it cannot determine.

## Use It

Ask Claude to draft a response to a fictional scheduling misunderstanding. Compare a polished but unsupported promise with a more limited accurate response. Do not use private conversations or clinical crises. Record date, model identifier as displayed, relevant prompts, commands, and actual results. Label fixtures, simulated participants, and hypothetical decisions. Claude Code is assumed; direct API calls are optional and may require separate credits.

## Ship It

Deliver fictional case, responses, review ledger, and annotated revision. Include a README with exact run/test commands and source credits, plus the [prediction, contribution, Frictional, and verification records](../../templates/README.md). Package a local candidate for inspection; the [Assignment map](../../assignments/fall-2026/README.md) specifies final delivery.

## Verify

Test invented commitments, unsupported certainty, and valid bounded language. Do not treat a favorable rating as evidence that a model feels empathy. Run checks on the packaged candidate. Record outcomes and remaining limits in VERIFICATION.md; revise and repeat Ship It → Verify when needed. Explain what changed in your understanding, without inventing difficulty or a required conclusion.

## Irreducibly Human

**AI should** draft alternative wording and flag unsupported claims.

**Human should** decide what is appropriate in context and avoid attributing feelings or commitments without evidence.

Record the actual split in CONTRIBUTIONS.md: what you did, what Claude contributed, what you accepted, changed, or rejected, and what still needs understanding or permission. A generated narrative does not establish human participation or consent.
