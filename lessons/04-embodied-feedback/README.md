# Lesson 4 — A description is not a physical measurement

**Predict → Build It → Use It → Ship It → Verify**

Reading: [02 tier 2 embodied and sensorimotor.md](../../chapters/02-tier-2-embodied-and-sensorimotor.md) — “How embodied skill is actually taught.” Tools: Claude Code and Python standard library. Prerequisites: prior lessons and retained predictions/evidence. Suggested pacing: one class session plus practice; Canvas supplies dates.

## Predict

Will a written procedure predict all the feedback needed to sort a few harmless household objects? Record an expected mismatch. Save an original expectation, confidence estimate, assumptions, and possible falsifier in PREDICTIONS.md before seeing the output. Add later observations without rewriting the original.

## Build It

Build a Python observation log comparing planned step, observed outcome, uncertainty, and adjustment. Define units and observation categories; use an accessible alternative task when needed. Make an initial attempt before requesting a complete solution. Work in learning-artifacts/04-embodied-feedback/ with main.py, test_main.py, inputs, and outputs. Explain what the mechanism checks and what it cannot determine.

## Use It

Ask Claude for a simple sorting procedure, then perform the task yourself or analyze a clearly labeled supplied observation trace. Note feedback unavailable from the original text. Record date, model identifier as displayed, relevant prompts, commands, and actual results. Label fixtures, simulated participants, and hypothetical decisions. Claude Code is assumed; direct API calls are optional and may require separate credits.

## Ship It

Deliver procedure, observation log, parser, and adaptation note. Include a README with exact run/test commands and source credits, plus the [prediction, contribution, Frictional, and verification records](../../templates/README.md). Package a local candidate for inspection; the [Assignment map](../../assignments/fall-2026/README.md) specifies final delivery.

## Verify

Test missing observations and contradictory units. Distinguish an actual physical trial from a text simulation; neither proves all robots lack the capacity. Avoid collecting sensitive personal measurements. Run checks on the packaged candidate. Record outcomes and remaining limits in VERIFICATION.md; revise and repeat Ship It → Verify when needed. Explain what changed in your understanding, without inventing difficulty or a required conclusion.

## Irreducibly Human

**AI should** draft a procedure and organize observations.

**Human should** perform or accurately label the observation task, notice feedback, and decide adjustments.

Record the actual split in CONTRIBUTIONS.md: what you did, what Claude contributed, what you accepted, changed, or rejected, and what still needs understanding or permission. A generated narrative does not establish human participation or consent.
